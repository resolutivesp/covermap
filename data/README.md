# `data/` — inputs, provenance and licences

Every file the pipeline reads. Nothing here is generated by CoverMap except `coverage_matrix.csv`,
which is the project's own curated work.

**Why this file exists.** "Open data" is a claim until someone can tell, per file, where it came
from and whether they are allowed to use it. This table is the answer. Licences below were checked
against the publisher's own licence page, not assumed from convention.

---

## Not included, and why

**GBIF occurrence points.** Earlier drafts carried 43 *Echis ocellatus* occurrence records from
GBIF, used to sanity-check the eco-zone ranges. No script in this repo reads them, and
redistributing GBIF-mediated records properly requires citing the download DOI, which was not
recorded at the time. Rather than ship data we cannot attribute correctly for a step we no longer
run, the file was removed and the GBIF citation dropped from the briefs. Species presence in the
current model comes from documented ecological-zone ranges, cited in `methods.md`.

## Reproducing from these inputs

```bash
python3 code/build_v2.py      && python3 code/make_v2_visuals.py && python3 code/make_report_v2.py
python3 code/nigeria_build.py && python3 code/nigeria_outputs.py
python3 code/india_build.py   && python3 code/india_outputs.py
python3 code/make_index.py    && python3 code/make_methods_page.py
```

Then check yourself:

```bash
python3 code/verify_ghana.py verify_nigeria.py verify_india.py \
        verify_crosscountry.py verify_figures.py
python3 code/audit_parameters.py
```

The audit is the one that matters. It says six load-bearing numbers remain **NOT CONFIRMED** —
searched for, not found in the literature. That is the honest state of this tool.
